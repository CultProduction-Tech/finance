# API показателей Культа для MCP

`GET /api/second-brain/kpi?startDate=2026-01-01&endDate=2026-11-16`

API входит в приложение dashboard. Авторизация: `Authorization: Bearer <отдельный служебный ключ MCP>`.
Юрлицо фиксировано: Cult. Принимается ровно по одному startDate/endDate:
реальные даты 2000–2099, endDate >= startDate, разница до 366 дней.
Любые дополнительные параметры, включая entity и snapshot, отклоняются.
Browser session и CRON_SECRET не дают доступа к этому endpoint.
POST, PUT, PATCH и DELETE отвечают 405; Next.js автоматически поддерживает
HEAD с той же авторизацией/обработкой, что GET, и OPTIONS (204, без финансовых данных).
Trailing slash перенаправляет на канонический URL.

## Конфигурация клиентов

`SECOND_BRAIN_API_CLIENTS` — непустой JSON-массив объектов:

- `id`: непустое уникальное имя интеграции;
- `sha256`: уникальный SHA-256 токена, ровно 64 строчных hex-символа;
- `scopes`: массив, единственное разрешённое значение — `cult:finance:kpi:read`.

Администратор создаёт ключ из 32 случайных байтов в base64url (43 символа)
средствами менеджера секретов. Raw хранится только в закрытом окружении
авторизованного финансового MCP, hash — в окружении dashboard.
Не передавать raw пользователям, агентам или продюсерским инструментам,
не добавлять в Git, chat, логи и отчёты.

Потребитель обязан авторизовать конечного пользователя **до вызова API**,
включая поиск и выдачу источников. Этот репозиторий не содержит реализации
такого MCP auth; перед production-активацией нужны конкретный runtime,
владелец secret store и подтверждённая матрица пользователей.
Scope включает полный KPI payload, в том числе сведения о проектах и бюджетах.

Коды: 503 — отсутствующий/пустой/невалидный JSON, дубли id/hash, неизвестный scope
или любая испорченная запись (отключается весь endpoint); 401 — неправильный ключ;
403 — известный ключ с пустым scopes; 400 — недопустимый период/параметры.
Конфигурация проверяется до ключа, даты — после авторизации.

## Семантика данных

Формулы остаются в существующем `/api/kpi`, выбор компании закреплён сервером.
Обёртка возвращает `{entity, period, source, fetchedAt, data}`.

- Параметры принимают дни, однако финансовый обработчик считает **полные месяцы**.
  Указанный period не означает дневную точность расчёта.
- В текущем/будущем месяце `factProfit` и `factRevenue` используют `planValue`
  ОПиУ PlanFact; в закрытом месяце — `factValue`. Это отдельно от `budgetProfit`
  из бюджетов. Не смешивать их при интерпретации.
- `fetchedAt`/`syncedAt` не гарантируют свежесть источников: есть fetch cache.
  В среду и пт–вс по Москве деньги могут подменяться снимком того же точного
  периода, снятым до окна. Без подходящего снимка возвращается live;
  PlanFact вызывается до подмены, поэтому его сбой даёт 502 даже со снимком.
- `planFactFrozen` и `sources.planfact="frozen"` отмечают подмену. `planFactAsOf`
  — подпись границы окна, а не timestamp реально использованного снимка;
  снимок может быть старее. Смешанный frozen/live ответ не получает `snapshot:true`.
- Неуспешный ответ/исключение KPI превращается в нейтральный 502 без upstream деталей.
  **Частичный сбой amoCRM/отсутствующий бюджет остаётся HTTP 200** со статусом
  в `data.sources` и нулями в затронутых полях; текст статуса может содержать
  подробности источника. MCP должен проверять sources, а не только HTTP status.
- GET и авторизованный HEAD могут создавать локальные `data/snapshots/`
  при здоровых источниках вне freeze; upstream бизнес-записей они не выполняют.
  Машинный ключ не открывает другие dashboard API и browser session.

## Локальная проверка

18.11.2026: на Next.js 16.2.0 / Node 20.20.2 с исходным package-lock:
unit 7/7, TypeScript и production build прошли; HTTP-матрица — 66 запросов
через настоящий Next/KPI и Postman simulation, включая parity с Cult KPI,
отказы доступа, методы, соседние маршруты, деградацию, 429 и freeze.
Полный lint имеет две существующие ошибки и два предупреждения в UI-компонентах;
затронутый API и тестовые файлы проверяются отдельно.
Production-установка и production-конфигурация этими результатами не подтверждаются.

Воспроизведение (существующий Node 20.20.2 через mise, Postman CLI >=1.70):

```sh
npm ci
node --test tests/second-brain-access.test.mjs
AUTH_SECRET=synthetic_build_only RESEND_API_KEY=re_synthetic_only npm run build
npx --no-install tsc --noEmit
npm run lint
node tests/second-brain-http.mjs
```

Последняя команда сама запускает Postman simulation на loopback 4619 и реальный
production-build Next на loopback 4620, не публикует результаты в Postman cloud.
Порты должны быть свободны. Все ключи, сессии и данные синтетические.
Копия build без fetch cache и отдельный snapshot-каталог создаются во временной
папке и удаляются после проверки. Логи и сгенерированные Postman коллекции —
во временной папке; можно задать `FINANCE_VALIDATION_OUTPUT`.
Фиксированные часы preloaded только в тестовый Node-процесс.
Stand-in основан на типах/вызовах клиента, не удостоверяет реальный контракт
PlanFact/amoCRM или права их production-ключей.

## Установка и откат

1. Подтвердить фактические host/repo/branch/SHA/PM2 command/env source;
   старого handoff недостаточно. Снять закрытые backups release/build и env,
   сохранить snapshots/notes; не печатать полный env или PM2 environment.
2. Завершить review проверенного SHA и проверку MCP user auth. Подтвердить
   допустимость полного payload, degraded 200 и согласованные лимиты запросов.
3. Администратор через secret manager добавляет отдельную запись финансового
   клиента, сохраняя прежних. Валидирует **весь** JSON до применения;
   raw — только в MCP, hash — в dashboard. Никаких production токенов в тестах.
4. Разместить проверенный release по действующему процессу; restart должен
   перечитать фактический источник env. Выполнить согласованный smoke доступа,
   200/parity и регрессий UI/auth/cron, учитывая snapshot-записи GET.
5. При отказе остановить нового потребителя, восстановить прежний валидный JSON
   и перечитать env; при регрессии вернуть сохранённый release/build.
   Если клиентов раньше не было, отсутствие SECOND_BRAIN_API_CLIENTS отключает
   API с 503. Snapshots/notes не удалять. Скомпрометированный raw не восстанавливать.
