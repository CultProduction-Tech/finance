# Чтение денежного потока для MCP

GET `/api/second-brain/cashflow`, без параметров. Тот же Bearer-ключ и настройка
SECOND_BRAIN_API_CLIENTS, что для KPI; дополнительный секрет не нужен.
MCP проверяет почту/роль owner до обращения. Маршрут жёстко выбирает Культ,
не принимает entity, snapshot или иные параметры. Cookie/cron не заменяют API-ключ.

GET возвращает баланс и дневные точки fact/plan по формулам графика. При живом
расчёте диапазон включает текущий месяц и три следующих по Москве.
Машинный запрос не создаёт и не обновляет снимки графика.
Отчёт о движении денег дополняет ОПиУ.

Во время заморозки подходящий снимок, сохранённый до начала окна, возвращается
целиком. На границе месяца диапазон может начинаться в предыдущем месяце.
`planFactFrozen: true` отмечает заморозку, `planFactAsOf` содержит подпись границы
окна, а `syncedAt` — время сохранения снимка. Флаг `snapshot: true` относится к
отдельному браузерному запросу снимка.

При отсутствии подходящего снимка в заморозку выполняется живой расчёт. При
его сбое API возвращает `502` с сообщением `Dashboard data unavailable`.
Вне заморозки сбой источника также даёт `502`, даже когда у графика есть снимок.

`OPTIONS` возвращает `204` и `Allow: GET, OPTIONS`. После проверки ключа
`HEAD` получает `405` с тем же `Allow`.

Размещение: обычный выпуск приложения после принятия ветки. Никаких миграций
или дополнительных переменных окружения нет. Установить вместе с изменением
точного списка API в middleware. MCP-адаптер уже подготовлен отдельно.

Модульные проверки запускаются через
`node --test tests/second-brain-access.test.mjs tests/second-brain-cashflow.test.mjs`.
После сборки `npm run build` локальный стенд `node tests/second-brain-http.mjs`
проверяет также методы и запись снимка у машинного, браузерного и cron-клиентов.
